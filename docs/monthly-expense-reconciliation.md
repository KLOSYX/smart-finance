# 月度支出对账

总览、家庭收支和家庭财务洞察页共用对账卡片，支持选择历史月份。数据来自只读接口 `GET /api/analytics/reconciliation?month=YYYY-MM`，不依赖 AI、不自动新增流水、不修改现有统计接口。

## 计算口径

- 资产推算支出 = 上月末资产 + 本月已记收入 − 本月末资产。
- 已记净支出 = 本月支出 − 本月支出退款，允许负值。
- 待解释差额 = 资产推算支出 − 已记净支出。
- 转账不计收入、支出；只有转账两端账户均纳入资产范围时，余额变化才能相互抵消。
- 使用整个家庭账本的全部已入账流水，不受流水表分页、角色、分类或类型筛选影响。
- 当前月截至今天；未来日期的流水和快照不参与当前月的对账。

旧收支汇总接口会将负净支出截断到零，本次未改动其行为。因此净退款月份，对账卡片的“已记净支出”可能与旧“本月支出”指标不同，对账明细注明这一口径差异。

## 快照边界

期初取上月末当天或之前的最后一条快照，期末取本月末（当前月取今天）或之前的最后一条快照。不会使用边界之后的快照倒推过去。

仅纳入当前未归档、在截止日前已有快照的资产。历史月份不能还原已删除资产或过去的归档状态，页面明确提示此限制。

- `snapshots_ready`：已结束月份中，范围内所有资产在两个边界日期均有快照。这只表示日期完整，不保证账户或流水完整。
- `estimated`：沿用较早快照，或本月尚未结束。展示每项资产实际快照日期与问题，不掩盖时间错位。
- `unavailable`：无资产、任一资产缺少期初基准，或月份尚未开始。推算支出和差额返回 `null`，不把缺失当作零。

新增资产可能是补登旧账户，不能自动认定期初余额为零。确实从零开始的账户可以明确补录零值期初快照。

## 解释边界

当前模型没有独立负债余额、估值收益、资产划入划出或对账调整项，所以展示的是未校正估算，不能称为真实消费或确定的漏记金额。主要干扰包括信用卡消费与还款跨月、借款与还本、未记收入、投资涨跌、公积金缴存、账户范围变化和旧快照。

正差额可提示检查漏记支出、投资损失、偿还旧债及范围外转出；负差额可提示检查漏记收入、投资增值、新增借款、未还信用卡消费及重复入账。这些是排查方向，不是已确认原因。差额为零也可能是遗漏互相抵消。

资产明细按余额变化绝对值排序，提供排查入口，不把单个资产变化自动归为消费或收益。要进一步得到校正后的消费估计，需要可核验的负债和非消费变动数据，并避免将已记理财收入再次作为收益调整重复计算。

## 验证

`backend/tests/test_reconciliation.py` 使用独立内存数据库覆盖正负差额、退款、转账、零基准、缺失基准、旧快照、当前月截止、归档/未来资产、空数据和日历边界；接口验证同时检查只读行为。
